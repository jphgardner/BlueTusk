# Ecosystem performance qualification

`ecosystem-performance.yml` is a manually dispatched, exact-commit local capacity gate for Jobs, Workflows, Projections and Documents. Dispatch it with a full 40-character `candidate_sha` that already contains this workflow, the budget contract and verifier, and type `RUN-ECOSYSTEM-PERFORMANCE`. It requires a clean checkout on the dedicated Windows Ryzen 7 5800X benchmark runner, Docker in Linux-container mode, Python and .NET from `global.json`. The workflow has read-only repository permissions and performs no packaging, release or publication step.

The gate runs **two independent campaigns** of each workload. Each Jobs/Workflows storage campaign offers 30 minutes per product with seeded high-entropy payloads; each Projections soak and Documents fixed-cardinality churn runs for 30 minutes. The wall time is several hours because campaigns are sequential and include setup, drain, recovery and verification. Each harness uses a dedicated disposable PostgreSQL fixture. The gate rejects missing runs, wrong payload mode, failed logical/recovery checks, insufficient measurement time or sparse storage/service observations. A successful pass means only that this workload and runner met the explicit local thresholds below. It does not establish production capacity, indefinite storage bounds or performance leadership.

| Workload | Minimum throughput | Maximum p99 | Storage ceiling |
| --- | ---: | ---: | ---: |
| Jobs | 20 durable completions/s | 10 s hot, 3 s cold | 64 MiB runtime relations; 2 MiB/min late net growth; 64 KiB cluster WAL/accepted |
| Workflows | 5 durable completions/s | 30 s hot, 12 s cold | 128 MiB runtime relations; 4 MiB/min late net growth; 256 KiB cluster WAL/accepted |
| Projections | 5 transactions/s | 5 s commit, 10 s projection, 5 s inbox | 2 GiB owned storage, 1 GiB retained slot, 8 MiB WAL/transaction |
| Documents | 500 committed transitions/s | 500 ms save | 1 GiB peak owned relations, 16 MiB/min late owned growth, 8 GiB whole database, 64 MiB/min late whole-database growth, 64 KiB WAL/transition |

The exact numeric contract, minimum durations, fixture resource guardrails and PostgreSQL image digests are in [`eng/ecosystem-performance-budgets.json`](../../eng/ecosystem-performance-budgets.json). These are conservative initial qualification thresholds, **not measured claims**. The gate must actually run and pass on a committed candidate before reporting success. Jobs/Workflows late growth uses the final-half endpoint rate and physical relation peak from the raw sample stream. Their WAL budget divides the PostgreSQL cluster's before/after WAL-position delta by accepted work, so the fixture must stay dedicated during each campaign. The Documents sustained scenario must attest `AttachedContent` storage; its verifier also requires the 15-cell inline JSONB sweep, distinct stable payloads, hard-kill recovery, maintenance coverage and disk headroom. The 1 GiB owned-relation check includes detached content, while the whole-database cap covers the entire disposable database. Projections verifies the committed pipeline, p99s, retained-slot and owned-storage peaks and WAL per transaction.

Each artifact retains raw harness reports, workload logs, fixture observations, before/after source captures, runnable harness binary snapshots, Documents scoped source snapshots and bindings, a budget snapshot, and a manifest containing the full candidate SHA and SHA-256 of every retained file. The gate builds once, runs the captured binaries without rebuilding and verifies their live hashes after each campaign. The offline verifier checks the artifact hashes again and repeats the budget checks. Git cleanliness and before/after source-tree hashes bind all campaigns to the same commit; the Jobs source fingerprint and Documents executable bindings add harness-specific checks. The archived evidence has a 90-day GitHub Actions retention period.

Windows benchmark-runner capacity, Docker CPU/memory throttling, PostgreSQL version and workload distribution limit comparisons with real deployments. Jobs/Workflows currently support at most one hour per product invocation; this gate uses half-hour repeats, not a continuous multi-hour single invocation. Projections keeps permanent Events identities/outbox/inbox in its owned fixture; its storage ceiling is finite rather than a plateau assertion. Documents uses the existing bounded physical-space guard. Longer isolated endurance, multi-host fleets, representative data and production operating limits remain separate release work.
